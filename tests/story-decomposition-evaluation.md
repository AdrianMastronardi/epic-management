# Complete dependency graph evaluation

Evaluated on 2026-10-23 for issue #3. Two independent agents each received an isolated skill copy and the same 18 [planning inputs](story-decomposition-cases.md). One copy came from release `v0.4.0` (`841eb6372e33465c3c200a12cc6530d394688fad`); the other contained this change's candidate instructions, references, and templates. Neither agent received the issue, proposed fix, expected outcomes, rubric, conversation history, or the other agent's results. Both were restricted to fixture evidence and their isolated copies, with no GitHub access or product implementation.

Each agent performed one planning pass per case, including the stated variants within cases 6 and 15: 18 cases per revision, 36 case decisions total. They produced scope, prerequisite, projection, readiness, and remaining-action decisions rather than full EPIC bundles. The input file's SHA-256 was `58acfdfe301fe73741f7273d196cf39ab8d81f003552c1da5ac43d4cebf2b20b`. The coordinating agent then assessed both outputs against the revised [rubric](story-decomposition-rubric.md); this assessment was manual, while the planning runs were independent agent evaluations.

Against the revised policy, the candidate met the behavioral criteria in all 18 cases; the release baseline met them in 10. The eight changed outcomes are cases 3 and 11–17. These baseline differences reflect the intentional policy change, not evidence that the previous release violated its own former cycle exception. Controls resolved identically are regression evidence, not evidence of improvement.

For example, the baseline described case 3 as “The story overview cycle is executable,” whereas the candidate diagnosed that “the complete graph nevertheless cycles A, B, A.” In case 14, the candidate explicitly withheld affected body, branch, PR, relationship, and bundle writes despite previous publication approval, and preserved the two existing issue identities. These decisions address planning behavior beyond structural validator success.

## Deterministic checks and limits

The initial implementation had 37 tests. After the follow-up review below, the 42-test suite passes with PyYAML 6.0.3 and with site packages disabled to exercise the fallback parser. Regression fixtures cover mixed and documented-only cycles, transitive paths, self-dependencies, linear and diamond DAGs, independent stories, external prerequisites, reciprocal informational links, escaped pipes, metadata and routing errors, and unchanged OKF consumer tolerances. They also cover missing distribution sections, formatted story identifiers, exact diagnostic line numbers, and dependency-context distribution checks. Both validator entry points are exercised in standalone and embedded layouts, including failing CLI invocations. Python compilation, the installed structural skill validator, Ruff, Prettier 3.9.10, and markdownlint-cli2 0.23.3 also pass. Formatting tools were run from locally cached packages because offline npm resolution could not locate registry metadata.

One focused on validators and the other on workflow and coverage. Both received the same explicit patch and source/documentation payload, had all tools disabled, and performed static review only. The coordinating agent reproduced the concrete bugs locally and selected the changes; neither reviewer claimed to run tests.

The 18-case behavioral comparison above predates these review-driven fixes and clarifications. It was not rerun afterward; the post-review verification is the deterministic suite and static checks described here, not an additional independent planning trial.

This was one independent planning run per revision, not repeated trials or a live end-to-end publication test. The coordinating agent knew the intended change when scoring outputs. No actual GitHub writes, host-native Codex/Claude Code sessions, full generated EPIC packages, or implementation deliveries were tested by the behavioral evaluators. Shared instructions were evaluated; host-specific reliability and repeated-run consistency remain unmeasured. Local validators inspect declared internal table rows only: missing prose gates and cross-EPIC paths still require the semantic workflow review.
